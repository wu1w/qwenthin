# 2026-08-23 本地 Qwen3.8-27B 三 Agent 横向实测

这轮测试使用同一份 `Qwen3.8-27B-UD-Q8` 权重和同一个本地推理服务，比较当前 qwenthin、OpenCode 1.17.13 与 Claude Code 2.1.216。目的不是做排行榜，而是观察 Harness 对同一模型的完成率、工具轨迹、收束行为和代码修改质量有什么影响。

## 测试方法

- 从 qwenthin 现有测试集中选择 5 道此前没有用于三方横评的新题。
- 覆盖简单 Python、中等应用安全、困难数学、困难哲学和困难 SRE。
- 每个 Agent 使用独立完整源码树，每题每个 Agent 运行一次，并轮换运行顺序。
- 编码题使用隐藏语义检查、公开单测与测试完整性检查。
- 推理题按预先写好的四项要点人工复核，每题满分 4 分，统一外部时限为 240 秒。
- 三种 Harness 的 token 统计口径不同，因此不以 token 数直接排名。

## 结果

| 题目 | 难度 / 领域 | qwenthin | OpenCode | Claude Code |
|---|---|---:|---:|---:|
| c23 闰年世纪规则 | 简单 / Python | 通过；27.57s；7 次工具 | 通过；162.65s；21 次工具 | 通过；48.25s；11 次工具 |
| c17 灾难性正则回溯 | 中等 / 应用安全 | 通过；18.91s；4 次工具 | 通过；81.22s；10 次工具 | 通过；144.18s；11 次工具 |
| RF-M03 等待 HHTH | 困难 / 数学 | 4/4；101.35s | 4/4；63.09s | 240s 超时，无最终答案 |
| RF-P05 Newcomb 问题 | 困难 / 哲学 | 3.75/4；116.83s | 4/4；172.48s | 240s 超时，无最终答案 |
| RF-X05 区域 p99 故障 | 困难 / SRE | 4/4；72.32s | 4/4；131.64s | 4/4；198.76s |

| Harness | 完成率 | 总耗时 | 编码题平均工具调用 | 推理题得分 |
|---|---:|---:|---:|---:|
| qwenthin | 5/5 | 336.98s | 5.5 | 11.75/12 |
| OpenCode | 5/5 | 611.08s | 15.5 | 12/12 |
| Claude Code | 3/5 | 871.21s（含两次超时） | 11.0 | 4/12 |

本轮 qwenthin 总耗时比 OpenCode 少约 44.9%，比 Claude Code 少约 61.3%。它与 OpenCode 都完成了全部题目，但 qwenthin 的代码工具轨迹明显更短；OpenCode 的三道纯推理答案最准确。Claude Code 在两道纯推理题上没有及时提交最终答案，更像 Anthropic 兼容协议、系统提示结构或结束条件与本地模型不够匹配，而不是模型缺少相关知识。

## 这轮验证到的改动

1. **持久增量代码索引有效。** 两道编码题中，qwenthin 平均调用 5.5 次工具，OpenCode 为 15.5 次，Claude Code 为 11 次；qwenthin 能先取得有限的相关代码片段，再进入修改和验证。
2. **没有靠硬停止获得优势。** 5 次 qwenthin 运行的 trajectory note 都为 0，watchdog 均未触发。模型在正则题只使用很短的思考，而数学、哲学题自行展开到约一万字符，说明自动思考强度在按任务分配。
3. **软轨迹策略方向正确。** 普通测试修改、测试变红和短期摇摆只作为新证据交还模型，不再让无人值守模式立刻停机；本轮没有出现 Harness 抢夺停止决定的问题。
4. **长上下文评测不再人为灌水。** 最新长任务 runner 使用真实跨域 hop、注意力检查和运行轨迹，不再通过填充文本强制压缩三次，也不再把窗口写死为 16K。
5. **跨平台逻辑进入工具层。** macOS/Linux 使用 Bash；Windows 优先 Git Bash，缺失时回退 PowerShell，并由 Harness 选择 Python 启动方式，避免把平台判断塞进系统提示词。

## 横评后的两项追加修复

### 多行 `edit` 透明兼容 CRLF/LF

`edit` 现在把 LF、CRLF 和单独 CR 视为同一种逻辑换行来做唯一匹配，但只替换原文件中实际命中的字节区间，并让新片段沿用该区间的换行风格。文件其他部分不会被全局换行转换，混合换行下若逻辑片段出现多次仍会拒绝编辑。相同规则也同步到了 `run_code` 的内嵌 Python SDK。

新增回归覆盖：LF 请求编辑 CRLF 文件、CRLF 请求编辑 LF 文件、混合换行的唯一性保护，以及 SDK 路径。完整工作区结果为 **607 passed、0 failed、47 ignored**。

随后使用原 c23 闰年任务和真实 CRLF 源码树复测当前 qwenthin：22.8 秒完成，源码与测试均通过局部 `edit` 修改，没有退化到整文件 `write`；隐藏语义检查和 3 个单测全部通过，两个被修改文件仍保持全 CRLF。

### 定量推理的轻量数值复核

Harness 不增加常驻系统提示，也不强制第二轮生成。只有当非代码题同时包含概率、百分比、阈值等数量信号和计算、比较、推导等推理信号时，才加入一行隐藏提示：让模型在定稿前内部回代一次，并区分百分比、百分点和被求变量；一致时直接作答，不新增复核章节。

使用原 RF-P05 Newcomb 题重新实测后，模型正确给出单箱 `990,000`、双箱 `11,000`，将临界准确率表述为约 `50%`，没有再出现“预测准确率约 0.1%”的变量混淆，并在 240 秒时限内完成。原始横评表保留首次结果，复测结果应视为该缺陷的最新状态。

## 下一步值得优化的点

### 优先做

1. **明确 `--new` 与 `--session` 的组合语义。** 当前两者同时使用时，实际会生成另一个 session ID，评测脚本需要从 stderr 反查。建议设为互斥，或稳定输出机器可读的实际 session ID。

### 下一轮验证

2. **只在已有证据覆盖任务后轻量收束。** Newcomb 和数学题仍分别思考约 117 秒与 101 秒。不要设置固定思考长度；可以只在语义覆盖已完整、连续一段时间没有新结论时，提醒模型压缩已有事实并自行决定作答还是继续。
3. **扩大数值复核回归集。** 当前 Newcomb 复测已通过，下一步应加入单位换算、条件概率、百分点、对数尺度和不等式边界，确认窄触发不会影响普通聊天和代码题。
4. **改善正确答案的简洁度。** qwenthin 的 SRE 答案要点齐全，但明显比 OpenCode 长。可让最终答案阶段优先复用已经形成的结论，减少重复论证，同时保留模型自行决定是否继续的权利。
5. **单独校准 Claude Code 兼容层。** 重点检查 Anthropic 流式 thinking 块、结束原因、工具循环结束和最终文本提交，不宜把这两次超时直接归因于权重能力。

## 评测器校正

- 原计划中的 c22 `safe_join` 在 Windows 上基线即失败，原因是测试把 POSIX 路径字符串写死。本轮弃用 c22 并换为 c17，后续应把 c22 改成平台无关断言。
- c17 的旧隐藏检查扫描整个源文件。Claude Code 已修复活动正则，但因注释引用旧正则而被误判；检查现已限定为活动 `_EMAIL` 赋值，三方最终均判通过。
- 三方比较脚本会在基线提交前清理 `__pycache__` 和 `.pyc`，避免解释器缓存污染代码差异。

## 如何复跑

先构建 qwenthin，并确保 `opencode`、`claude` 和本地 OpenAI/Anthropic 兼容服务可用，然后设置服务地址和模型：

```powershell
$env:Q38_BENCH_ENDPOINT = "http://127.0.0.1:8080"
$env:Q38_BENCH_MODEL = "Qwen3.8-27B-UD-Q8"
py -X utf8 eval/compare_three_agents_five.py
```

可选环境变量：`Q38_BENCH_BIN`、`Q38_BENCH_SESSIONS`、`THREE_AGENT_RUN_ROOT` 和 `THREE_AGENT_OPENCODE_CONFIG`。如果没有提供 OpenCode 配置，脚本会在本轮输出目录自动生成只指向所填本地服务的配置。

## 限制

每题每个 Harness 只运行一次，这份结果适合定位工作流差异，不代表稳定胜率。正式比较建议至少重复 3 次，报告完成率、中位耗时、P90、工具调用数、代码差异大小和人工盲评得分。
